# DA1 word 모드 역공학 (2026-08-10) — **해독 완료**

`.ADT` 컨테이너 안 서브 이미지 89장이 쓰던 미해독 변형을 풀었다.
구현: `tools/da1w.py` (byte·word 양쪽을 처리하는 통합 디코더).

## 1. 결론

| 검증 | 결과 |
|---|---|
| word 모드 89장 (strict) | **89 / 89 통과**, 컬럼 6,080개 전부 정확히 `h` 행 전진 + 스트림 정확 소진 |
| byte 모드 203장 회귀 | **203 / 203 통과**, 기존 `da1.py` 와 **픽셀 완전 일치 (불일치 0)** |

즉 `da1w.py` 는 `da1.py` 의 상위 호환이다.

## 2. word 모드의 정체

`AGS.EXE` 에서 디코더를 직접 찾아 확정했다.

| 로드 상대 주소 | 역할 |
|---|---|
| `0x4680` | **컬럼 분배기** — `x`(=di)의 홀짝과 `w`의 홀짝을 보고 바이트컬럼/워드컬럼을 섞는다 |
| `0x47a0` | **워드 컬럼** 디코더 (평면 하나의 컬럼 하나) |
| `0x7e4a` | **바이트 컬럼** 디코더 (기존 byte 모드와 같은 표) |

핵심은 이것이다.

> **word 모드는 emit 이 16비트다.** 한 컬럼이 가로 2바이트를 덮으므로 컬럼 수 = `w >> 1`.
> **다만 `w` 나 `x` 가 홀수면 남는 1바이트 컬럼을 바이트 모드 디코더로 처리한다.**

이 혼합이 「컬럼 수 = w/2」 단순 가설이 전부 실패한 이유였다. 89장 중 22장이 `w` 홀수다.

VRAM 역/순참조 델타 표(opcode `0xD3`–`0xF2`)도 `AGS.EXE` 에서 그대로 추출했다.

## 2b. 역참조 델타 32개 — 기계어로 전수 검증 완료 (2026-08-10)

Ghidra 10.2.2 + GhidraDosToolbox(DOS 로더)로 세그먼트를 제대로 잡아 핸들러를 전부 뽑았다.
**`tools/da1w.py` 의 `BACKREF` 표는 32개 전부 기계어와 일치한다 — 고칠 것이 없었다.**

핸들러 골격 (opcode D3 예시, `1456:0626`):

```asm
MOV AH,CH          ; AX = (CH<<8)|피연산자 = 반복 횟수 n
MOV BP,AX
SHL AX,0x2
ADD AX,BP          ; AX = n*5          (언롤 블록 한 칸이 5바이트)
SUB AX,0x22aa
NEG AX             ; AX = 0x22aa - n*5 (언롤 블록 진입점)
MOV BX,SI          ; 스트림 포인터 대피
MOV SI,DI
ADD SI,0xfb00      ; ← **이 즉치가 델타다** (부호 있는 16비트, -1280)
MOV CX,ES
MOV DS,CX          ; 원본 = 같은 평면
MOV CX,0x4e        ; 78
JMP AX
```

언롤 블록 한 칸 = `MOVSW`(2바이트 복사, SI·DI +2) + `ADD SI,CX` + `ADD DI,CX`(각 +78)
→ **한 칸이 워드 하나를 복사하고 정확히 한 행(80바이트) 내려간다.** da1w.py 구현과 같다.

| opcode | 기계어 즉치 | 델타 | opcode | 기계어 즉치 | 델타 |
|---|---|---|---|---|---|
| D3 | `0xfb00` | −1280 | E2 | `0xfd7c` | −644 |
| D4 | `0xfc40` | −960 | E3 | `0xfebc` | −324 |
| D5 | `0xfd80` | −640 | E4 | `0xff5c` | −164 |
| D6 | `0xfec0` | −320 | E5 | `-0x54` | −84 |
| D7 | `0xff60` | −160 | E6 | `-0x4` | −4 |
| D8 | `-0x50` | −80 | E7~EA | `0x4c/0x9c/0x13c/0x27c` | +76/156/316/636 |
| D9 | `0xfd7e` | −642 | EB | `0xfeba` | −326 |
| DA | `0xfebe` | −322 | EC | `0xff5a` | −166 |
| DB | `0xff5e` | −162 | ED | `-0x56` | −86 |
| DC | (단축형) | −82 | EE | `-0x6` | −6 |
| DD | `-0x2` | −2 | EF~F1 | `0x4a/0x9a/0x13a` | +74/154/314 |
| DE~E1 | `0x4e/0x9e/0x13e/0x27e` | +78/158/318/638 | F2 | `-0x8` | −8 |

규칙: **델타 = −80×행 + 열오프셋(0, −2, −4, −6, −8)**. 양수는 「아래 행, 왼쪽 워드」로,
이전 컬럼이 이미 그려졌으므로 유효한 참조다.

`D2` 는 역참조가 아니라 **투명 스킵**이다(`DI += n*16 + n*64 = n*80`).
`F6~F8` 은 `CS:[0x15]` 의 세그먼트 표에서 **다른 평면**을 읽는다(한 칸 9바이트, CX=0x50).

**따라서 줄무늬의 원인은 델타가 아니다.** 아래 3절 참조.

## 3. 줄무늬의 진짜 원인 — 해결됨

한동안 줄무늬를 **역참조 델타 오류**로 오진했다. 델타는 처음부터 맞았다(2b절).

**진짜 원인은 프레임 간 VRAM 을 이어 주지 않은 것이다.**
`decode_full()` 이 호출마다 빈 평면을 새로 잡았기 때문에, 차분 프레임이
**이전 프레임이 남긴 화면을 역참조**할 때(D8 = 한 행 위, 1,619회 사용) 0 을 읽었다.
그래서 정확히 가로 방향 스미어가 났다.

`decode_full(data, planes=..., mask=...)` 로 VRAM 한 벌을 넘겨 순서대로 그리면
**줄무늬가 완전히 사라진다** (`gfx/png_anim/cumul_28.png`).

```bash
py tools/gfx_adt.py png                              # 프레임 단독 (차분이라 깨져 보임 - 정상)
py tools/gfx_adt_anim.py 0100B.ADT --base 0100B.GDT  # 누적 합성 (실제 화면)
```

## 3b. 인코더 — 만들지 않았다 (그럴 필요가 없었다)

word 모드 인코더는 **끝내 만들지 않았다.** 대신 AGS.EXE 의 분기 한 줄을 이용했다.

```asm
1456:0169   TEST word ptr CS:[0x9a],0x4000   ; 헤더 flags
            JNZ  0x46e2                      ; 세워짐 -> 바이트모드 (0x7e05)
            CALL 0x83c4                      ; 아니면 워드모드
```

**flags 에 bit14 를 세우고 이미 검증된 byte 모드 인코더(`tools/da1enc.py`)로 다시 쓰면
게임이 그대로 읽는다.** 프레임 28 실측: word 10,645바이트 → byte 10,296바이트(0.97배),
픽셀·알파 완전 일치.

구현: `tools/gfx_adt_credit.py`. 마지막 프레임을 **자기완결형**(사각형 전체 불투명)으로
다시 써서, 앞 프레임이 무엇을 남겼든 결과가 같아지게 했다.

결과: **시작 로고 화면(XENON + 행성)에 「번역 : THL.kr」 삽입 완료.**
컨테이너 재검증 29/29 프레임 디코드 성공, 디스크 이미지 반영 완료.

## 4. 반증된 가설 (기록 보존)

| 가설 | 결과 |
|---|---|
| byte 모드 표 그대로 | 356 평면 중 2개만 통과 |
| emit 2바이트 + 컬럼 = w/2 (**단순형**) | 전부 실패 — **홀수 컬럼 혼합을 빠뜨린 것이 원인이었다** |
| `w`/`x` 가 워드 단위 | 화면 폭 80바이트 초과로 성립 불가 |
| `n==0` 이스케이프 = 최대값(16/32) | 16개 조합 전부 실패 |
| 구간별 (개수, 값) 조합 | 최고 5/356 |

⚠ `0x434D`/`0x3C84`/`0x46C6` 의 `test word [bx+0xe40],0x4000` 은 **DOS 파일 핸들 플래그**다.
DA1 과 무관 — 헛짚기 쉬운 곳이다.

## 4b. 시작 로고(`ROGO.GDT`)의 죽은 띠 — 실기 추적 결과

크레딧을 로고 마크와 「C's ware presents」 사이 빈 공간(y258~276)에 넣었더니
**파일에는 들어 있는데 화면에 안 나왔다.** DOSBox-X 와 Neko Project II 양쪽에서 재현됐다.

**대조 실험으로 확정했다.** 같은 문구를 `y=200`(로고 마크 위)과 `y=265`(빈 띠)에
**동시에** 넣고 캡처하니 **y=200 만 보였다.** 파일에는 둘 다 있었다.

표식 막대를 4px 간격으로 훑어 경계를 좁혔다.

| 프레임 y | 화면 |
|---|---|
| ~245 이하 | ✅ 나온다 |
| **246 ~ 288** | ❌ **안 나온다** |
| 289 이상 | ✅ 나온다 |

원본에서 정확히 그 띠가 비어 있다. 게임이 스프라이트를 그린 뒤 그 영역을 덮어쓰는 것으로
보이며, 원본은 거기가 비어 있어 아무도 눈치채지 못했을 것이다.
그리기 호출부(`FUN_1456_00d5`)는 `di = x + y*80`, `ncol = w>>1` 만 세우고
**높이 제한이 없다** — 스프라이트 자체는 전부 디코드된다. 덮어쓰는 주체는 아직 특정 못 했다.

→ 크레딧은 **y226~245**(마크 아래쪽 끝)로 옮겼고 양쪽 에뮬레이터에서 표시를 확인했다.

### 헛짚은 것 (기록)

* 「원본이 투명한 자리라 인코더가 건너뛴다」 — 틀렸다. `da1enc.encode()` 로 사각형 전체를
  불투명하게 만들어도 화면은 그대로였다.
* `da1enc.py --flat` 은 **일부 평면만 쓰인 칸**에만 듣는다. 아무 평면도 안 쓴 칸은
  그대로 투명이라 이 문제에 무력하다.
* 테스트 함정: DOSBox-X 가 `out/run/xenon_ko.hdi`(kotest 가 만드는 사본)를 마운트하고 있어
  **낡은 이미지로 검증**한 적이 있다. `dbg/xenon_dbg.hdi` 로 매번 새로 복사해야 한다.

## 5. 결과

시작 로고 시퀀스는 `ROGO.GDT` 가 아니라 **`0100B.ADT`(29프레임)** 가 그린다.
목표였던 **시작 로고 화면 크레딧 삽입을 달성했다.**

크레딧은 총 4곳에 있다.

| 위치 | 방식 | 실기 확인 |
|---|---|---|
| **시작 로고 (C's ware)** | `ROGO.GDT` y226~245 | ✅ DOSBox-X · np2 양쪽 |
| 서시(에피그래프) 화면 | 엔진 텍스트 (overrides 1b) | ✅ np2 |
| `0100B.ADT` 프레임 28 (XENON + 행성) | word→byte 모드 재인코딩 | ⏳ 미확인 — 부팅~메뉴 구간에 안 나온다. **엔딩 시퀀스로 추정** |
| 저작권 배너 | `0100BB.GDT` 캔버스 24→48줄 확장 | ⏳ 미확인 (엔딩) |

`AGS.EXE` 의 파일명 배열이 `rogo → 0100b → xenon2 → st01~09` 순인 것으로 보아
뒤 셋은 엔딩 시퀀스다. 시작 화면에 나오는 것은 `ROGO.GDT` 하나뿐임을 실기로 확인했다.

## 6. 이 작업을 가능하게 한 도구

정적 분석이 막혀 있던 것을 뚫은 것은 **Ghidra 10.2.2 + GhidraDosToolbox** 조합이다.

- Ghidra 12.1.2 기본 로더는 16비트 세그먼트를 제대로 못 잡아 핸들러 주소가 어긋났다.
- GhidraDosToolbox 의 **DOS 로더**가 `x86:LE:16:Real Mode` + Segmented X86 Calling
  Conventions 로 임포트해 `Seg_2 = 1456:0000`(디코더 세그먼트)를 정확히 잡아 주었다.
- 확장은 **소스 빌드가 아니라 사전 빌드된 릴리스 zip**(Ghidra 10.2.2용)을 써야 한다.
  main 브랜치 소스는 다른 Ghidra 를 겨냥해 28개 오류로 빌드 실패한다.
- Ghidra 10.2.2 는 **JDK 17** 이 필요하다. `support/launch.properties` 의
  `JAVA_HOME_OVERRIDE` 로 고정하고 `~/.ghidra/.ghidra_10.2.2_PUBLIC/osgi` 를 지워야
  `osgi.ee=UNKNOWN` 오류가 사라진다.

추출 스크립트: `C:\thelife\asm_tools\work\scripts\DumpDa1.java`(핸들러 32개),
`DumpFlags.java`(진입부·flags 분기).
