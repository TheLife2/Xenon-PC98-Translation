# XENON ～夢幻の肢体～ 한국어 번역 파이프라인

PC-98 게임 XENON(1993, ジェネシス/Seedsware)의 한국어 패치 제작 도구.
영문 패치 프로젝트([Xenon-PC98-Tools](https://github.com/OldCorpo/Xenon-PC98-Tools) /
[Xenon-PC98-Translation](https://github.com/OldCorpo/Xenon-PC98-Translation))의 구조를 그대로 쓰되,
Shift-JIS로 표현할 수 없는 한글을 넣기 위해 **글리프 슬롯 할당 + 폰트 시트 생성** 단계를 추가했다.

원본 저장소 두 개는 **읽기 전용으로만 참조**한다. 이 프로젝트는 아무것도 수정하지 않는다.

> 번역 판단의 근거, 영문판·일본어판과의 차이는 [`TRANSLATION_NOTES.md`](TRANSLATION_NOTES.md) 에 정리돼 있다.

---

> 번역 판단의 근거와 영문판·일본어판 대비 차이는 [`TRANSLATION_NOTES.md`](TRANSLATION_NOTES.md),
> 만든 이미지를 실제로 돌려 보는 방법은 [`HOWTO_PLAY.md`](HOWTO_PLAY.md).

## 빠른 시작

```bash
py tools/koextract.py       # 원본에서 번역 작업 파일 생성 (최초 1회, 이후에도 안전)
                            # -> translation/_script-korean.txt 를 편집한다
py tools/koverify.py        # 번역문 검사
py tools/build.py           # 전체 빌드
py tools/build.py --run     # 빌드 후 에뮬레이터 실행
py tools/kodump.py S00      # 결과 확인 (삽입된 한국어를 되읽어 표시)
```

산출물은 `out/` 에 나온다.

| 파일 | 설명 |
|---|---|
| `out/xenon_ko.hdi` | 게임 이미지 |
| `out/font.tmp` | Neko Project II 계열용 폰트 시트 — **반드시 같이 배포** |
| `out/anex86.bmp` | Anex86용 폰트 시트 (포맷 동일) |

## 왜 폰트 시트가 필요한가

게임은 텍스트를 **PC-98 CG ROM(폰트 ROM)** 에서 가져다 그린다. 게임 파일 안에 폰트가 없다.
Shift-JIS에는 한글이 없으므로, **비어 있는 JIS 区(구)에 한글 글리프를 그려 넣고**
그 자리를 가리키는 Shift-JIS 바이트를 스크립트에 넣는 방식을 쓴다.

그래서 한국어 패치는 `.hdi` 하나로 끝나지 않는다. **커스텀 폰트 시트가 세트로 필요하다.**
실기 PC-98이나 폰트를 못 바꾸는 환경에서는 동작하지 않는다.
(영문 패치는 순수 ANK 반각 문자만 써서 이 문제가 없었다.)

### 폰트 시트 좌표 규칙

NP2kai 소스(`font/fontmake.c:308-310`, `font/fontpc98.c`)에서 확정하고,
区16点1 = `亜`(제1수준한자 첫 글자)로 실측 검증했다.

```
2048 x 2048, 1bpp, bottom-up BMP, stride 256, 비트 0 = 잉크(로더가 반전)

  x = 16 * 区                区 = JIS 상위바이트 - 0x20   (1..94)
  y = 16 * (点 + 32)         点 = JIS 하위바이트 - 0x20   (1..94)
  y = 0..15                  8x16 반각(ANK) 256자 띠
```

### 쓸 수 있는 슬롯 (전수 조사 결과)

| 区 | 내용 | 판정 |
|---|---|---|
| 1–8, 13 | 기호·가나·그리스·키릴·罫線·NEC특수문자 | 사용 중 |
| **9–12** | **반각 폰트가 16×16 공간에 복제된 영역** | ⛔ 건드리면 안 됨 |
| **14, 15** | 비어 있음 | ✅ 188칸 |
| 16–47 | 제1수준한자 | 예비 |
| **48–83** | 제2수준한자 — 한국어판에선 불필요 | ✅ 3,384칸 |
| **84, 85, 88** | 비어 있음 | ✅ 282칸 |
| 86, 87 | 로더가 읽지 않음 | ⛔ 사용 불가 |
| 89–92 | NEC선정 IBM확장 | 사용 중 |
| **93, 94** | 비어 있음 | ✅ 188칸 |

기본 할당 순서는 `区14,15,84,85,88,93,94`(658칸, 아무것도 희생 안 함) →
`区48-83`(제2수준한자). **총 4,042칸**으로 KS X 1001 완성형 2,350자가 여유 있게 들어간다.

## 파일 포맷

### `.CC` = 24바이트 헤더 + LZSS

```
[0x00..0x13]  원본은 "LCZ" + 잔여 바이트. 게임이 읽지 않는다
[0x14..0x17]  압축 전 크기 (LE32)
[0x18..    ]  Okumura LZSS (N=4096, F=18, THRESHOLD=2)
```

`xenon_lzss.exe`(MSVCR100 필요)와 `tools/kolzss.py`의 파이썬 구현이
**원본 37개 파일에서 바이트 단위로 동일**함을 확인했다. exe가 없으면 자동으로 파이썬으로 넘어간다.

### `.U.CC` 안의 텍스트 블록

```
FD <len> <본문 len 바이트> 00
```

원본 37개 파일 15,423 블록 전부가 이 규칙에 100% 들어맞는다.
본문에는 Shift-JIS 텍스트와 제어 바이트가 섞인다.

| 바이트 | 뜻 | 표기 |
|---|---|---|
| `04 xx` | 2바이트 명령 | `<$04><$xx>` |
| `05` | 1바이트 명령 | `<$05>` |
| `0A` | 줄바꿈 | `\n` |
| `0C` | 1바이트 명령 (카운트 대기 등) | `<$0C>` |

블록의 **선두·말미 제어열은 자동 보존**되므로 번역자는 본문만 신경 쓰면 된다.
본문 중간의 제어코드는 `<$XX>` 표기 그대로 위치를 유지해야 한다.

### 원본 도구와 달라진 점

| | 원본 (`xenreplacer.py`) | 여기 (`koreplacer.py`) |
|---|---|---|
| 순회 방식 | 마커 패턴 11개로 파일을 11번 훑음 | 블록 파서로 1번 |
| 길이 바이트 | **갱신 안 함** (영문판 13,405/15,423 블록 불일치) | 갱신함 |
| `\n` · `<$XX>` | 역변환 없음 → 영문판에 `¥n` 노출 버그 | 역변환함 |
| 라벨/파일명 | 번역 대상에 포함 (`xenon_01` 등) | 1,236개 제외 |

## 번역 작업 파일

`translation/_script-korean.txt` (UTF-8)

```
#EN You will now wake up.            <- 영문판 참조 (자동 생성, 편집 불필요)
//　　　　さぁ、あなたはこれから、目を覚まします。   <- 일본어 원문 (수정 금지)
　　　　자, 당신은 이제 곧 눈을 뜹니다.              <- 여기에 한국어를 적는다
```

* 빈 줄 = 미번역
* `#` 로 시작하는 줄은 주석
* `\n` = 줄바꿈, `<$XX>` = 제어코드. **개수와 순서를 바꾸지 말 것**
* `koextract.py` 를 다시 돌려도 **이미 적은 번역은 보존**된다

번역 단위 **9,436개** (전체 등장 14,035회 — 중복 대사가 많다).
99.5%는 영문 번역이 참조로 붙는다.

### 검사 규칙 (`koverify.py`)

| 등급 | 항목 | 이유 |
|---|---|---|
| 치명 | 연속 공백 3개 이상 | **게임이 크래시한다** |
| 치명 | 슬롯 미할당 문자 | 인코딩 불가 |
| 치명 | 블록 255바이트 초과 | `FD` 뒤 길이 바이트가 1바이트 |
| 치명 | 제어코드 개수 불일치 | 표시가 깨진다 |
| 치명 | **고유명사 배타 규약 위반** | 아래 참조 |
| 경고 | `…`(U+2026), `–`(U+2013), `—`(U+2014) | PC-98에서 제대로 안 그려짐 → `‥`, `-`, `―` 사용 |
| 경고 | 고유명사 누락 | 의도적 생략일 수 있어 경고만 |
| 경고 | 원문보다 넓은 줄 | 자동 줄바꿈에 기대게 됨 |
| 경고 | 220바이트 초과 | 상한 근접 |

## 고유명사 표기 규약

규약 문서는 [`translation/GLOSSARY.md`](translation/GLOSSARY.md),
기계가 읽는 표는 [`translation/terms.json`](translation/terms.json).

### ⚠️ 주인공 이름 — 한자와 가타카나를 반드시 구분한다

| 원문 | 한국어 | 화자 태그 | 뜻 |
|---|---|---|---|
| `宏治` | **코지** | 1,662줄 | 현실 세계의 주인공 |
| `コウジ` | **코우지** | 1,268줄 | 기억을 잃은 상태의 주인공 |

작가가 의도한 서사 장치다. 가타카나 표기는 주인공이 자기 이름조차 모르는 구간에만 쓰인다
(「コウジ‥‥？　それが私の名前なのか‥‥？」). **영문 패치는 둘 다 `Kouji` 로 뭉개서 이 구분을 잃었다.**

검사기가 배타 규약을 **치명적 오류**로 잡는다.

```
[ OK ] 코우지‥‥? 그게 내 이름인가‥‥?      원문 コウジ
[치명] 코지‥‥? 그게 내 이름인가‥‥?        원문 コウジ  <- 배타 위반
[ OK ] ［코지］：그렇습니다.                  원문 ［宏治］
[치명] ［코우지］：그렇습니다.                원문 ［宏治］ <- 배타 위반
[경고] ［그］：그렇습니다.                    이름 생략 (의도적일 수 있음)
```

`koextract.py` 는 해당 줄 위에 `#!! 표기 コウジ→코우지` 힌트를 자동으로 붙인다.

## 대량 번역 (배치 작업)

9,406줄을 배치로 쪼개 여러 작업자(사람이든 에이전트든)가 나눠 맡을 수 있다.

```bash
py tools/kobatch.py split 160      # 미번역분을 batches/src_NNN.txt 로 분할
                                   # -> 각자 batches/ko_NNN.txt 를 작성
py tools/kocheck_batch.py 000      # 배치 하나 기계 검사
py tools/kocheck_batch.py --all    # 전체 요약
py tools/kobatch.py merge          # 작업 파일에 반영
py tools/kobatch.py status         # 진행률
```

### 사용자 확정 수정 — `translation/overrides.txt`

배치를 다시 돌리거나 다른 작업자가 다르게 옮겨도 **여기 적힌 값이 이긴다.**
`merge` 가 배치 결과를 반영한 *뒤에* 이 파일을 덮어쓴다.

```
# 원문의 ';' 는 발음기호 'zi:non' 의 장음 콜론 오타. 콜론으로 확정.
//Ｘ　Ｅ　Ｎ　Ｏ　Ｎ\n\n　[ z i; n o n ]
Ｘ　Ｅ　Ｎ　Ｏ　Ｎ\n\n　[ z i: n o n ]
```

원문 키가 작업 파일에 없으면 `merge` 가 오류로 보고한다(오타로 무효가 된 항목을 잡기 위해).

번역 지침은 [`translation/TRANSLATE_GUIDE.md`](translation/TRANSLATE_GUIDE.md).

### 배치 형식

입력 `src_NNN.txt`
```
#NO 001
#EN [Kouji]: Of course not...
#!! 표기 宏治→코지
//［宏治］：そんなことは‥‥。
```

출력 `ko_NNN.txt` — **`번호|한국어` 한 줄씩, `#NO` 개수와 정확히 같은 줄 수**
```
001|［코지］：그런 건‥‥.
```

일본어 원문을 출력 파일에 옮겨 적지 않으므로 원문이 훼손될 위험이 없다.
`kobatch.py merge` 가 번호로 짝을 맞추고, 누락·중복·범위 초과를 전부 보고한다.

### `kocheck_batch.py` 가 확정적으로 잡는 것

LLM 이 눈으로 볼 필요가 없는 항목은 전부 기계가 잡는다.

```
ko_000.txt : 160줄, 치명 2 / 경고 1
  004 | 치명 | 연속 공백 3개 이상(게임 크래시) : 아니요…   그럴 리가
  004 | 치명 | 금지 문자 U+2026 … : 아니요…   그럴 리가
  004 | 경고 | 고유명사 누락 '코지' : 아니요…   그럴 리가
```

줄 수·번호 연속성·중복 · 제어코드와 `\n` 개수 일치 · 연속 공백 · 금지 문자 ·
고유명사 배타 규약 · 255바이트 상한 · 원문 대비 길이.

화면 폭은 **640px = 반각 80칼럼 = 한글 40자**. 게임이 자동 줄바꿈하므로 하드 리밋은
아니지만, 일본어 원문 길이를 상한으로 삼는 것이 안전하다.

## 테스트

**`np2fmgen\np2.exe` (Neko Project II, PC-9801)** 를 쓴다.
`np21.exe`(PC-9821/IDE)는 이 Anex86 SASI 이미지를 못 읽는다
(「システムディスクをセットしてください」에서 멈춘다).

```bash
py tools/build.py --run
```

`out/run/` 에 에뮬레이터·폰트·이미지를 모아 실행한다. **부팅에 25~40초** 걸린다.

자동 스크린샷·키 입력이 필요하면 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` 와
`PostMessage(WM_KEYDOWN/WM_KEYUP)` 를 쓴다. 창을 앞으로 끌어내지 않아도 되고
포커스를 뺏지 않는다.

## 그래픽 안의 글자

그림은 `.GDT` / `.ADT` 파일이고 **DA1**(ANNEX 라이브러리) 형식이다. 공개 문서가 없어
`AGS.EXE` 의 디코더를 읽어 복원했다. 디코더·인코더·주입이 모두 갖춰져 있어
**PNG 로 고치면 그대로 게임에 들어간다.**

```bash
py tools/da1enc.py frompng gfx/raw/X.GDT edited.png gfx/edit/X.GDT
py tools/build.py                        # 7단계에서 gfx/edit 를 이미지에 반영
py tools/gfx_check.py --png X.GDT        # 이미지에서 되읽어 확인
```

그림 210개 중 **일본어가 들어간 것은 `XENON2.GDT`(엔딩 타이틀) 하나뿐**이고
이미 한국어판이 만들어져 있다. 타이틀 로고·메뉴는 원래 영문이다.

절차·주의사항은 **[HOWTO_GRAPHICS.md](HOWTO_GRAPHICS.md)** 참조.

## 남은 작업

* **폰트 다듬기** — 현재 굴림 16px 자동 렌더링. 획이 뭉치는 글자는 수동 보정이 나을 수 있다
* **`AGS.EXE` 내부 문자열** — 실행 파일은 손대지 않았다
  (조사 결과 일본어 문자열이 없다. UI 텍스트는 전부 `.CC` 스크립트에 있다)
* **배경 의존 그림 44개** — DA1 의 화면 참조 명령을 쓰는 차분 이미지라
  PNG 왕복이 불가능하다. 고칠 일이 생기면 별도 접근이 필요하다

| 파일 | 역할 |
|---|---|
| `tools/kocfg.py` | 경로·슬롯 풀·SJIS 변환·이스케이프·블록 파서 |
| `tools/koscript.py` | 텍스트 블록 ↔ 표기 문자열 변환 |
| `tools/koextract.py` | 원본 → 번역 작업 파일 생성 |
| `tools/koalloc.py` | 글자 → 区点 슬롯 할당 (append-only) |
| `tools/kofont.py` | 할당표 → 폰트 시트 2종 |
| `tools/koverify.py` | 번역문 사전 검사 |
| `tools/koreplacer.py` | 스크립트에 한국어 삽입 |
| `tools/kolzss.py` | LZSS 압축/해제 (exe + 파이썬) |
| `tools/kohdi.py` | HDI FAT12 파일 교체 (클러스터 할당 포함) |
| `tools/kodump.py` | 빌드 결과 확인 |
| `tools/kobatch.py` | 배치 분할 / 병합 / 진행률 |
| `tools/kocheck_batch.py` | 배치 단위 기계 검사 |
| `tools/build.py` | 전체 오케스트레이션 |
| `tools/seed_prologue.py` | 실증용 프롤로그 시드 번역 |
| `tools/da1.py` | DA1 그래픽 **디코더** (info / verify / png) |
| `tools/da1enc.py` | DA1 그래픽 **인코더** (roundtrip / bgdeps / frompng / topng) |
| `tools/gfx_extract.py` | 디스크 이미지에서 그림 210개 추출 |
| `tools/gfx_sheet.py` | 렌더한 PNG 를 대지로 묶기 |
| `tools/gfx_xenon2_ko.py` | 엔딩 타이틀 한국어판 생성 (글자 지우기 + 한글 렌더) |
| `tools/gfx_build.py` | `gfx/edit/*.GDT` 를 디스크 이미지에 주입 (build.py 7단계) |
| `tools/gfx_check.py` | 디스크 이미지에서 그림을 되읽어 검증 |
| `tools/kotest.py` | 에뮬레이터 자동 실행 + 스크린샷 |

의존성: Python 3 + Pillow (`py -m pip install pillow`)
